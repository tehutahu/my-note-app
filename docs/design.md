# 手書きノートアプリ 設計案

> これは初期の背景・比較資料です。実装時は [実装引き継ぎ書](../START_HERE.md)、[詳細技術設計](architecture.md)、[受入基準](acceptance.md) を正として読み進めてください。ファイル形式、上限値、環境、工程は詳細設計で決定しました。初期版のバックアップ取り込みはコピーのみとし、下記の置換案は将来へ延期しています。

## 1. 目的と現在の方針

Galaxy Tab S7+とGalaxy S23 Ultraで手書きしたノートを、特定メーカーに限定されないWindows PCでも閲覧・編集できるようにする。

開発費・維持費を抑えるため、第一候補を**PWA（ブラウザーで使え、ホーム画面にも追加できるWebアプリ）**とする。AndroidとWindowsで同じ画面・保存形式・描画処理を使う。

これは採用候補であり、S Penの実機検証前に最終決定しない。現在はユーザーの希望により設計のみ。コード実装、依存追加、公開、有料サービスの契約は行わない。

## 2. 必須要件と実現方法

| 要件 | 初期版の設計 |
| --- | --- |
| Androidタブレット・スマートフォン | 画面幅に応じて切り替わるPWA。Tab S7+とS23 Ultraを実機検証対象にする |
| スタイラスで手書き | Pointer Eventsでペン種別・座標・筆圧を取得。入力中は即時描画し、筆跡を座標列として保存 |
| 書く・消す | ペン、蛍光ペン、筆跡単位の消しゴム、元に戻す・やり直す |
| 単純な図形 | 直線、長方形、楕円。ドラッグして作成 |
| 太さ・モードの切り替え | 太さ、色、ペン／蛍光ペン／消しゴム／図形をツールバーから選択 |
| 背景の選択 | ページ単位で無地・横罫線・方眼を選択。背景色も選択可能 |
| フォルダ階層 | フォルダ作成、名前変更、親フォルダ変更、ノート移動。循環する移動は禁止 |
| Windowsで参照・編集 | 同じPWAで読み込み、閲覧・編集。初期版はファイルによる手動受け渡し |
| PDF出力 | ノートの全ページを、背景・図形・筆跡を含むPDFとして保存 |
| PDF取り込み | PDFの各ページを背景として取り込み、その上に書き込む。元のPDFを保持 |

「筆跡単位の消しゴム」は触れた一筆全体を消す方式。線の一部分だけを削る消しゴムは、必要性を確認して追加する。

## 3. 構成候補の比較

| 構成 | 費用と開発作業 | ペン入力 | Windows対応 | 判断 |
| --- | --- | --- | --- | --- |
| PWA | 1つの実装を共有。静的配信のみで開始可能 | ブラウザー経由。筆圧・誤入力防止・遅延は実機確認が必要 | 同じアプリで閲覧・編集 | 最初に試す |
| Flutterなどの共通アプリ | Android/Windowsのビルド・配布・検証が必要 | OS連携の選択肢が増えるが、実機確認は必要 | Windows向けアプリを配布 | PWAの実機評価が不十分なら再検討 |
| Androidネイティブ＋Windows用ビューアー | 2種類の実装を保守する | Android固有の入力処理を調整しやすい | 別途実装 | 入力品質を最優先するときの候補 |

PWAは開発・保守の範囲を小さくするための提案。ネイティブアプリと同等の書き心地を保証するものではない。

## 4. 保存と端末間の共有

### 初期版：ローカル保存＋ファイル受け渡し

- ノート、筆跡、PDF原本をIndexedDBに保存する。
- 保存処理は一筆の終了時などにまとめ、描画を妨げない。保存完了後に「保存済み」と表示する。
- Androidから専用ファイルを書き出し、USBや利用中のファイル共有手段でWindowsに渡す。
- Windowsで読み込むと同じノートを編集できる。逆方向の受け渡しも可能。
- PDFは閲覧・配布用、専用ファイルは筆跡やフォルダを保って編集を続けるための形式とする。
- 初期版に自動同期は含めない。AndroidとWindowsの内容が自動で揃う仕組みではない。

単一ノートの書き出しと、フォルダ階層を含む全体バックアップを用意する。同じIDのデータを読み込む場合は、無条件に上書きせず「コピーとして取り込む」を既定にし、置き換える場合は差分となる更新日時と対象を確認できるようにする。

専用形式はバージョン付きのデータと添付ファイルをまとめた形式を想定する。具体的なコンテナ形式は実装時に決定する。PDF原本を含めて、別端末で復元可能にする。

### データ保護

ブラウザー内保存だけを恒久的なバックアップとみなさない。ブラウザーデータ削除、端末故障、容量不足に備え、バックアップ書き出しをわかりやすく配置する。永続ストレージの要求が可能な場合は利用するが、それだけで消失を防げるとは扱わない。

容量不足・保存失敗は明示し、「保存済み」と誤表示しない。フォルダ・ノート削除はゴミ箱に移し、完全削除は別操作にする。

### 将来：自動同期

自動同期を追加する場合は、既存クラウドストレージ連携または同期サーバーを比較する。認証、複数端末の競合、削除の伝播、オフライン変更の再送が必要になるため、独立した開発段階にする。無料枠のあるサービスでも、容量や転送量による制限・課金条件を採用時に確認する。

同時編集は初期版の対象外。同期を導入しても、競合した変更を黙って捨てず別コピーとして保持する方針とする。

## 5. ノートと入力の設計

ノートは固定サイズの複数ページで構成する。初期の新規ページはA4縦を既定とし、PDF由来のページは元の縦横比・回転を尊重する。無限キャンバスは初期版に含めない。

描画データは画面のピクセル位置ではなくページ座標で保存する。拡大縮小や端末の解像度が変わっても、筆跡・図形・PDF背景の位置が一致するようにする。

入力中の表示と確定した筆跡を分けて描画し、可能な場合はまとめて届いたポインター座標も使う。筆圧が取得できない入力では一定の太さにする。

通常は「ペンで書く・指で移動／ピンチ拡大」を既定にする。指で書くモードも明示的に選べるようにする。ペン入力中は指入力を抑制するが、OS・ブラウザーが手のひらをどのように通知するかは実機で確認する。S Penの側面ボタンは確認できた場合の補助操作とし、必須操作は画面から行えるようにする。

### 保存する主な情報

| データ | 主な項目 |
| --- | --- |
| フォルダ | ID、親ID、名前、作成日時、更新日時、削除日時 |
| ノート | ID、フォルダID、タイトル、ページ順、更新日時、リビジョン |
| ページ | ID、幅・高さ、背景設定、PDF添付ID・ページ番号、描画要素 |
| 筆跡 | ID、ツール、色、太さ、座標・筆圧列 |
| 図形 | ID、種類、始点・終点、線色、線幅 |
| 添付 | ID、MIMEタイプ、PDF原本、サイズ |
| バックアップ | 形式バージョン、書き出し日時、データ、必要な添付 |

ページの保存はトランザクションで扱う。Undo/Redoは操作単位とし、PDF背景は消しゴムの対象にしない。

## 6. PDF処理

候補はPDF.js（ページ表示）とpdf-lib（PDF生成・元ページの取り込み）。どちらも現段階では追加しない。導入前にユーザーの承認を得る。

- 読み込み：ファイルを検査し、原本を保存。表示するページを中心に描画し、全ページの高解像度画像を常時メモリーに持たない。
- 編集：元PDFの文字やレイアウトは変更せず、上の注釈レイヤーに筆跡・図形を保存する。
- 出力：元PDFページを可能な範囲で保持し、筆跡・図形・背景を合成する。筆圧表現や蛍光ペンの透明度も画面と一致させる。
- PDF出力後の注釈は、他のPDF編集ソフトで個別に再編集できることを初期要件にしない。再編集には専用形式を使う。
- パスワード付き・破損・非対応PDFは、初期版では理由を表示して取り込みを中止する。既存ノートは変更しない。
- 大容量PDFは対象端末で上限を測定し、読み込み前にサイズを確認する。数値上限は未決定。

PDF出力の確認では、ページ回転、異なる用紙サイズの混在、罫線、蛍光ペン、縦横表示を含める。

## 7. 画面構成

- ライブラリー：フォルダ階層、ノート一覧、新規作成、PDF取り込み、バックアップ読み書き。
- エディター：タイトル、保存状態、ツールバー、ページ表示、ページ一覧、PDF出力。
- タブレット／Windows：フォルダ・ページ一覧を横に置き、筆記領域を広く取る。
- スマートフォン：一覧を開閉式にし、主要なペン操作をコンパクトに配置する。拡大してもツール操作を維持する。

## 8. 費用と配布

ローカル保存とファイル受け渡しなら、アプリ用の同期サーバーやデータベースの維持費は不要。開発と実機検証の手間はかかる。

PWAのインストールとオフライン利用には配信方法の整備が必要。Androidから利用する本番環境はHTTPSを前提にする。開発PCのlocalhostと、Androidから開くPCのLANアドレスは条件が異なる。

配布先は実装後に選ぶ。無料枠の静的ホスティングを使えば現金支出を抑えられる可能性があるが、サービスの制限と条件は採用時に確認する。公開・契約は今回の設計作業に含めない。独自ドメインとアプリストア配布は初期版では不要。

オフライン利用は、アプリ本体とPDF処理に必要なファイルを端末にキャッシュした後を対象とする。外部CDNへの常時接続を前提にしない。

## 9. 開発順序と合格条件

### 段階1：S Penの最小実機試作

ペン、消しゴム、筆圧、指移動、拡大縮小だけを作る。Tab S7+とS23 Ultraで、手を置いたまま日本語の小さな文字を書き、遅延・線の抜け・誤入力・座標ずれを確認する。Windowsではマウスでも描けることを確認する。

**合格条件：ユーザーが普段の筆記に使えると判断できること。** 満たさない場合はこの時点でPWA構成を見直す。

### 段階2：基本ノートと復元

複数ページ、図形、背景、フォルダ、ローカル保存、Undo/Redo、専用形式での読み書きを実装する。

**合格条件：** 再起動後に復元でき、Android→Windows→Androidの受け渡しで筆跡・背景・フォルダ階層を保持できる。保存失敗を検出できる。

### 段階3：PDF入出力

依存追加の承認後にPDF取り込みと出力を実装する。

**合格条件：** 複数ページのPDFに書き込み、出力をWindowsの別のPDFビューアーで開いて位置と見た目を確認できる。専用バックアップからPDF背景も復元できる。

### 段階4：日常利用の仕上げ

PWAインストール、オフライン動作、バックアップ導線、ゴミ箱、容量不足への対応を整備する。

**合格条件：** インストール後、機内モードでも既存ノートの閲覧・筆記・保存・再表示ができる。両Android端末とWindowsで主要操作を確認する。

自動テストは座標変換、フォルダ循環防止、保存と復元、バックアップ互換性などに使う。JavaScriptを変更した場合は作業規約に従い `npm test` を実行する。ペンの書き心地は自動テストだけでは判定しない。

## 10. 初期版から外す機能

自動クラウド同期、共同編集、手書き文字認識、手書き内容の全文検索、無限キャンバス、音声録音、Samsung Notes独自形式からの直接移行。

既存のSamsung Notesからの移行は、対象端末でPDF書き出しが可能なら、そのPDFを取り込む経路を想定する。既存の筆跡を一筆ずつ再編集できる形で移行するものではない。
